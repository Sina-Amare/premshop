# ADR-0027 — Operator-written text is restricted Markdown through one renderer

**Status:** Accepted · 2026-10-20

**Context.** Until now the only formatted text the operator could write was the category introduction: raw HTML in `Category.intro_html`, printed with `|safe`, under an admin help text that said the HTML would run on the page. Anyone holding a staff login, or anyone who took one over, could put a script on the pages where customers pay. Escaping that field closes the hole but not the need behind it, and the need is growing. Product pages are moving to sections the operator writes — benefits, what the customer receives, a comparison table, the steps after payment, the conditions before buying, free text — and guides follow. That text needs paragraphs, lists, bold, links, a sub-heading and a table. It is typed into the panel by one person who will not hand-write HTML, and none of it may be able to carry anything that runs.

**Decision.**

1. **One function.** `apps.core.richtext.render_markdown(text, heading_levels=(3,))`, with one template filter over it, `{% load richtext %}{{ value|markdown }}`. Every piece of operator-written formatted text goes through it: product sections now, the category introduction and guides as they are rebuilt. It lives in `core` because `catalog` and the later `cms` both depend on `core`, and `core` depends on neither. `mark_safe` is allowed in this module and in the constant markup of `apps/core/templatetags/fa.py`, nowhere else, and a test enforces that.
2. **Two layers.**
   - **markdown-it-py**, CommonMark, raw HTML off, linkify off, tables on. A tag the operator types is printed as text. Constructs outside the subset — code spans and blocks, block quotes, horizontal rules, the underlined heading form, images — are switched off in the parser, so their characters print as typed instead of vanishing. Its link check is replaced: the library's own is a blocklist of four schemes that lets `data:image/…` and `//host` through; ours accepts `http`, `https`, `mailto` and paths on this site, and nothing else.
   - **nh3** (Python bindings to the Rust sanitizer ammonia) over the result, with its own allowlist: the tags `p`, `br`, `strong`, `a`, `ul`, `ol`, `li`, `table`, `thead`, `tbody`, `tr`, `th`, `td`, `bdi` and the heading levels the caller allows; `href` on `a`, `rel` on `a` with the one value below and no other, `start` on `ol` so a list that resumes at 3 is numbered from 3; no `style`, `class`, `id`, `title` or `lang` anywhere, which also suits a content-security policy without `unsafe-inline`; URL schemes `http`, `https` and `mailto`; a relative URL only if it is a path on this site after a browser's own clean-up, so `/\host` and `/<tab>/host` are refused as the other sites they are. `script` and `style` go with their content. This layer is tested on its own with raw HTML, in the shape it would arrive in if the parser ever let markup through.
3. **Links.** A path on this site (`/products/…`) is an internal link and carries no `rel`. Every other link carries `rel="nofollow noopener noreferrer"`. No link carries `target`: a link opens where it was clicked.
4. **Headings.** The page says, through `heading_levels`, which levels are free below its own headings: a product section leaves `h3` (its title is the `h2`), a category introduction leaves none (it sits directly under the page's `h1`), a guide can leave `h2` and `h3`. A heading above the allowed range moves down to the nearest allowed level; one below it, or any heading where none is allowed, becomes a paragraph. `h1` is never on offer and the function refuses a request for it: the page's title is its only `h1`.
5. **Persian.**
   - Each run of Latin text — a brand, a model name, a URL — is wrapped in one `<bdi>`, so «VS Code» or «12 Months Family Plan» keeps its order inside a right-to-left line. A run ends on a letter, a digit or one of `+ # % /`, so the full stop of the Persian sentence around it stays outside; brackets are never inside a run, because a run holding one half of a pair leaves the other half to be mirrored the wrong way. Attributes are never touched.
   - A run continues through the edges of bold and links, and its `<bdi>` holds them: `**Chat**GPT` and `ChatGPT **Plus**` are one name each. Two isolates side by side in a right-to-left line swap places, so a `<bdi>` per piece would show «Plus ChatGPT»; a test measures the reading order in Chromium. Where bold or a link also holds Persian, it is split in two at the run's edge, as a browser splits misnested formatting.
   - A single newline is a line break (markdown-it's `breaks`). The operator types into a plain textarea the way they type into a messenger, and a newline that silently became a space is a defect they could not see in their own text.
   - `*word*` and `_word_` drop their marks and read as plain text instead of becoming `<em>`. Persian is not set in italics, and stray asterisks in front of a customer read as a broken page. Emphasis is `**bold**`.
   - A numbered list typed with Persian digits («۱.») is a list, as «1.» is. CommonMark reads only ASCII digits as list numbers, so the marker's digits are converted before parsing.
6. **Dependencies.** markdown-it-py, until now present only through `rich` under the development tools, and nh3 become runtime dependencies, pinned by `uv.lock`. `pip-audit` checks both in CI with the rest of the environment.

**Alternatives considered.**

- **Plain text with `linebreaks`.** Safe by construction, but no lists, no links and no table; the comparison section would become prose pretending to be a table, or a picture of one.
- **Raw HTML through a sanitizer.** The operator would hand-write HTML, and every page would rest on the sanitizer alone, with no layer in which raw markup is simply not accepted.
- **bleach.** Deprecated by its maintainers in January 2023, and built on html5lib, which has had no release since 2020.
- **A hand-written sanitizer.** Parsing HTML the way a browser does is the hard part, and the published bypasses for this class of code — mutation XSS, entity-encoded schemes, the `/\` and tab tricks — are exactly what a home-grown version misses. Our own code is kept to the narrow parts (the link allowlist, heading levels, `<bdi>` runs), each covered by the attack corpus in `apps/core/tests/test_richtext.py`.
- **A WYSIWYG editor.** A JavaScript dependency in the panel whose output is HTML, the input this decision refuses; and the formatting the sections need is small enough to type.

**Consequences.**

- Outside the subset, the operator's characters reach the page as typed, and a heading arrives at a level the page allows. Two things are dropped without a trace: a link's title and a table column's alignment, which the parser emits as attributes the allowlist does not hold.
- The form that saves this text should reject what is outside the subset — an HTML tag, a heading the page will not take, an image — with a Persian message, so the operator learns at save time and not from the page. That check is not part of this function and is not built yet.
- Lists need styling where they are shown. The stylesheet's reset removes list markers, so a `ul` or `ol` from this function shows no bullets or numbers until its container sets them; `list-style-type: persian` gives Persian numerals.
- A line that starts with Persian digits and a full stop but does not become a list item — the second line of a paragraph that begins «۲. …» — prints with Latin digits. That is the price of converting markers before the parser sees them.
- An internal link written as a full URL (`https://premshop.ir/…`) counts as external and gets `nofollow`. Internal links are written as paths.
- An autolink inside link text (`[see <https://…>](/x)`) prints as part of the outer link's text. HTML cannot nest one link in another: a browser ends the outer link where the inner one opens and leaves it empty.
- A Latin run that crosses into a link also holding Persian (`ChatGPT [Plus ماهانه](/x)`) splits that link into two links to the same address.

**Assumptions.** One operator, trusted but not infallible, whose staff login is what an attacker would want: the renderer makes that login useless for putting script on the storefront; it does not police what the operator chooses to say. The text is short, so parsing on every render costs nothing worth caching. Both dependencies stay maintained; each is small, and either can be replaced behind this one function without touching a template.

**Revisit when.** The operator needs something the subset cannot express — an image inside text, a quotation, a code sample: widen the allowlist and the corpus together, never one without the other. Markdown in a textarea proves a burden once the first ten or so products are entered: the answer is an editor that writes this same subset, not HTML input. A second person gets a staff account, which makes the save-time check mandatory. Either dependency is abandoned or carries an advisory. The site gains a setting for its own address, at which point full URLs on the shop's host can count as internal.

**Amendment — 2026-10-20.** The condition above arrived the same day: `SITE_URL` is now the shop's address (`config/settings/base.py`, required over https in production). A full address whose scheme is http or https and whose host is exactly `SITE_URL`'s now counts as internal and carries no `rel`, as a path does, because guides link to product pages by full address. The match is on the whole host, so `premshop.ir.example.com`, `premshop.ir@example.com` and `www.premshop.ir` stay external, as does any `mailto:`; `apps/core/tests/test_richtext.py` holds those cases. The consequence above that a full URL on the shop's host gets `nofollow` no longer holds. One helper now sits beside the renderer without changing it: `isolate_latin`, behind the `|bdi` filter, wraps the Latin runs of a plain one-line field in `<bdi>` the same way and reads no Markdown; it escapes the text and builds its markup with `format_html_join`, so `mark_safe` is still allowed only where this ADR says. Headings, point 4: a text whose first heading lands inside the free range but below its first level now moves every heading up by that difference before the mapping above, because an untitled «متن آزاد» section, which leaves `h2` and `h3` free, opened with an `h3` straight after the page's `h1` when written with the `###` its field's help teaches. A caller that leaves one level free is unaffected.
