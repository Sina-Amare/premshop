# ADR-0025 — Catalog implementation: money as whole toman, one price function, a seeded shop

**Status:** Accepted · 2026-09-05 · implements ADR-0014 (flat catalog, no FTS) and ADR-0021 (promotional pricing)

**Context:** S3 builds the first thing a customer sees. The contracts settled the shape — four flat tables, `effective_price` as the only price rule, `icontains` on a normalised column — and left three gates to the owner: region values, catalog breadth, images. This records what building it decided.

**Decision:**

- **Money is `DecimalField(max_digits=12, decimal_places=0)`**, whole toman, through one `MoneyField()` definition that every money column in the project will use. There is no fractional toman; Decimal keeps arithmetic exact all the way to the order snapshot; zero decimal places documents the unit in the schema itself.
- **Region values:** `global`, `ir`, `us`, `eu`, `tr`. The owner's ruling named Iran; the others exist so a Turkey-region account can be labelled honestly rather than as «جهانی». Warranty stays as the data model had it; delivery type likewise.
- **The two promotion CHECKs carry `violation_error_message` in Persian.** Django validates `CheckConstraint`s in `full_clean()`, so the admin form shows the database's own rule as a Persian sentence. No custom `clean()` exists to drift from the constraint.
- **Search folds on save and on query** (`apps/catalog/search.py`): Arabic ي/ك → Persian ی/ک, half-space → space (what phones type instead of it), three digit scripts → ASCII, harakat and tatweel removed, Latin lowercased. Lossy on purpose; for matching, never display. `search_text` is `editable=False` and **deliberately unindexed** — a btree cannot serve a substring match and the catalog is a few dozen rows. Rate-limited with the same limiter as login, which moved to `apps.core` so catalog does not depend on accounts.
- **"Featured" on the home page is the newest eight active products.** No flag until the operator asks for one; with a catalog this size the newest are the ones worth showing.
- **A card shows the cheapest available plan.** The struck-through pair therefore appears on a card only when the promotion is on the cheapest plan — which is the honest "from" price, not a defect.
- **The add-to-cart control ships complete but inert** (`data-cart-pending`, `action="#"`): plan selector, stepper capped at one on a customer-input plan, one primary button, disabled with an explanation when nothing is available. S4b sets the action and re-validates the cap on the server.
- **django-unfold for the admin** until S7. The product form carries specs and plans inline; spec titles come from a `<datalist>` of titles already in use, so the same fact is spelled the same way on every product.
- **A `seed_catalog` command** (DEBUG only, idempotent, `--reset`) fills the shop with twelve realistic products so pages are judged full; icons come from Simple Icons on jsDelivr into `MEDIA_ROOT`, and a product without one gets a monogram tile designed for that case.
- **Playwright is a dev dependency.** Chrome's CLI could not click, type, paste, or go below ~485px wide. The browser tests skip themselves when no browser is installed.

**Alternatives considered:** an integer money type (fine today, but a Decimal column is what every payment gateway and accounting export expects, and the cost is nothing); a `featured` flag (a field nobody asked for); indexing `search_text` (decoration — `pg_trgm` is the named upgrade); a real cart endpoint now (S4b's job, and shipping half of it means shipping its bugs early).

**Consequences:** The home page is the catalog, so `/` changed meaning and the style guide moved to `/styleguide/`. Media is served by Django in development only; production needs the reverse proxy to serve `MEDIA_ROOT`, which lands with S6b. The product page has a query budget test (≤15) and the category grid one that does not grow with product count; both are the tests that will catch the next N+1. Open-questions #2 (the real product list) is still open; the seed is a stand-in, not content.

**Amendment — 2026-10-13 (owner's review of S3).** Two decisions above are superseded by what the owner ruled after using the shop:

- **Region is not a product property.** The five region values recorded above are gone, with the column (`catalog 0003`). Most of what this shop sells has no region, and a field defaulting to «جهانی» printed a meaningless badge on every card and a meaningless row on every product page. A product that genuinely is region-bound now says so in a `ProductSpec` row the operator adds — which the seed already demonstrated for the Turkey and US items. The brief's §4 requirement is met by that row.
- **Search matches word by word, over an `aliases` column.** `icontains` on the whole normalised query could never find «چت جیپت», because that is a different transliteration of ChatGPT, not a different encoding of the same letters: folding ي→ی cannot bridge it. Products now carry `aliases`, an admin-editable list of the spellings customers actually type, folded into `search_text` on save and never rendered; and the query is split into words, each matched separately, so word order and an extra word do not decide the answer. Still `icontains`, still unindexed, and `pg_trgm` is still the named upgrade — the gap this closes is vocabulary, not fuzziness.

**Amendment — 2026-10-14 (owner's instruction).** Two things the operator must control per product, rather than the code deciding for every product: **whether a quantity can be chosen at all**, and **what the buyer is asked for**. `Plan.max_quantity` is new, defaults to 1, and at 1 the buy box renders no stepper — a disabled control is one the buyer still tries to use. Two CHECKs guard it: 1..10, and exactly 1 whenever the plan requires the customer's own account details, which until now was only enforced in JavaScript. `requires_customer_input` and `customer_input_label` already existed and already worked; the label is now shown verbatim on the product page («برای فعال‌سازی ایمیل حساب OpenAI شما را می‌پرسیم.») and both carry admin help text, because a field whose effect the operator cannot see is a field they will not use.

**Amendment — 2026-10-14b (owner's review, with a survey behind it).** Three changes to what a product states and how a category page is framed.

**The delivery-type filter is deleted.** It rendered `DeliveryType.choices` wholesale, so a category offered filters for types it did not contain — the gift-card category filtered by «گیفت کارت» — and it printed the enum's own labels at the customer, including «روی اکانت خود مشتری», which is how an operator describes a buyer to themselves rather than how a shop addresses one. Surveyed across eleven Iranian shops in this market: account type is a facet on none of them, delivery method on none, and of six small shops with eight products or fewer, zero offer attribute filters; the single exception is a theme default showing a price slider over three items. With two or three products per category every filter returns everything or nothing. The product count stays and nothing else. *Revisit when* a single category passes roughly fifteen products — and then add **sort** first (جدیدترین · ارزان‌ترین · گران‌ترین), not filter. The enum's label is now «روی اکانت شخصی شما».

**`Product.renewable`**, default false. The owner's rule: a product can be renewed if it says so. The page prints the row only when the flag is true, so an untouched product claims nothing; there is deliberately no grey «قابل تمدید نیست», and no row at all on a gift card, which has no period to renew. This matches the market, where renewability is never a facet and never a badge — it is written into the product title or offered as a plan.

**`ProductSpec.is_key`** covers everything else a product might need to state — whether an account is shared and with how many, how many devices, which region, any condition peculiar to one product. None of those is true of every product, which is the same reasoning that deleted `Product.region` in 0003; a row marked مهم prints beside the title as well as in the table. The market's vocabulary, seeded so the admin's datalist suggests it: seats are counted in «کاربره» (never «نفره», which is prose, and never «ظرفیت», which is the PlayStation idiom and means quota on an AI account), streams are «پخش هم‌زمان: ۲ دستگاه», and device *types* («Mobile / PC / TV») are the honest form where a number would over-promise.
